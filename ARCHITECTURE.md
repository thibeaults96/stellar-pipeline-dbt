# Stellar Pipeline — Architecture Guide

Every file in the repo, what it does, and why it's here.

## How the system works

The game has three layers:

1. **dbt project** (`dbt_project/`) — a real dbt project with SQL models, YAML configs, and CSV seed data. When the player clicks "dbt run", actual dbt executes against a local DuckDB database.

2. **Game engine** (`stellar_dbt/`) — Python package that wraps dbt. Manages game state (objectives, XP, narratives), checks player work against dbt artifacts and file contents, and fires story beats at the right moments.

3. **Web UI** (`frontend/`) — Next.js app with a Monaco code editor, objective panel, terminal output, DAG viewer, and narrative panel. Talks to the game engine through a FastAPI server (`backend/`).

The player edits real `.sql` and `.yml` files. The game engine checks those files and dbt's output to determine whether objectives are met.

## Root files

### `.gitignore`
Keeps generated files out of version control: `.venv`, `node_modules`, `.next`, DuckDB databases, dbt `target/` and `logs/`, game state file (`.stellar_state.json`).

### `LICENSE`
MIT license.

### `README.md`
Setup instructions, level overview, troubleshooting, project structure summary.

### `pyproject.toml`
Python package definition. Lists all dependencies (dbt-core, dbt-duckdb, FastAPI, uvicorn, typer, rich, pydantic, pyyaml, duckdb). Defines the `stellar` CLI entry point. Used by both `uv sync` and `pip install -e .`.

### `setup.sh`
One-command install script. Detects `uv` (preferred) or falls back to `pip`. Installs Python deps, frontend deps (`npm install`), and initializes Level 1.

### `dev.sh`
Starts the game. Kills any stale processes on ports 8000/3000, resets game state, starts both the FastAPI backend and Next.js frontend using `concurrently`. Auto-detects `uv` or venv.

### `uv.lock`
Lock file generated by `uv sync`. Pins exact dependency versions for reproducible installs.

## `dbt_project/` — The real dbt project

This is the working directory the player edits. Files here get overwritten by the game engine when switching levels.

### `dbt_project.yml`
dbt project configuration. Sets project name (`stellar_pipeline`), paths for models, seeds, tests, and target output.

### `profiles.yml`
dbt connection profile. Points at a local DuckDB file (`stellar.duckdb`). One thread, dev target. Lives inside the project dir so dbt can find it via `--profiles-dir`.

### `seeds/raw_shipments.csv`
Source data for shipments. 5 rows of cargo data with columns like `shipment_id`, `origin_planet`, `cargo_mass` (has 'kg' suffix), `status` (uppercase). Overwritten by each level with level-specific data (e.g., Level 2 adds NULL shipment_ids, Level 4 adds `updated_at`).

### `seeds/raw_planets.csv`
Source data for planets. 5 rows including Null Meridian (NM-00), which is uncharted and not a Federation member. Used across all levels.

### `models/sources/federation_sources.yml`
dbt source definition. Tells dbt where the raw seed tables live (`schema: main`). Overwritten by levels that need freshness config or custom source definitions.

### `models/staging/stg_planets.sql`
Locked reference model. A complete, working staging model that players can read but not edit. Shows the CTE pattern: source -> renamed -> output. Present in every level as a learning example.

### `models/staging/stg_shipments.sql`
The first file players edit in Level 1. Starts as a skeleton with comments explaining the pattern. Players fill in column renames, casts, and cleaning logic. Overwritten by each level's `initial_files`.

### `models/marts/fct_trade_routes.sql`
The mart model players build in Level 1. Starts as a placeholder. Players add ref() calls, joins, and aggregation. Carried forward (pre-filled) in later levels.

## `backend/` — FastAPI API layer

Thin HTTP wrapper around the game engine. The frontend calls these endpoints.

### `__init__.py`
Empty. Makes `backend` a Python package so imports work.

### `server.py`
All API endpoints:
- `GET /api/status` — current game state, objectives, pending narratives
- `POST /api/start/{level_id}` — initialize a level (writes files, clears state)
- `POST /api/run` — execute `dbt run`, check objectives, fire narratives
- `POST /api/test` — execute `dbt test`, check objectives
- `POST /api/check` — re-check file-based objectives without running dbt
- `POST /api/reset` — restart current level
- `GET /api/files` — list editable files
- `GET/PUT /api/files/{path}` — read/write a file (with path traversal protection and locked file enforcement)
- `GET /api/sources` — list seed CSV files
- `GET /api/sources/{name}` — preview source data (CSV or DuckDB query)
- `GET /api/preview/{model}` — query a built model's results from DuckDB
- `GET /api/manifest` — DAG nodes and edges from dbt's manifest.json
- `GET /api/levels` — list available levels
- `GET /api/hints/{id}` — get hint for an objective

### `serializers.py`
Converts game engine objects (dataclasses, Pydantic models, tuples) into JSON-serializable dicts for the API responses.

## `stellar_dbt/engine/` — Core game logic

### `__init__.py`
Empty. Package marker.

### `game_engine.py`
Central orchestrator. Static methods:
- `start_level(id)` — applies level files, clears state, fires LEVEL_START narratives
- `run()` — calls dbt seed+run, checks all objectives, fires narratives for completed objectives
- `test()` — calls dbt seed+test, checks objectives, fires narratives
- `check_objectives()` — shows current objective state without running dbt
- `status()` — returns game state + objectives for display

Key behaviors: objectives only evaluate on `run`/`test` (not on start/check). The `all_models_pass` objective is gated on all other objectives being complete first. Per-objective completion events (`OBJECTIVE_{id}_COMPLETE`) trigger narrative beats.

### `dbt_runner.py`
Wraps subprocess calls to the dbt CLI. `run()` does `dbt seed` then `dbt run`. `test()` does `dbt seed` then `dbt test`. Auto-finds the dbt binary in the current venv.

### `artifact_reader.py`
Parses dbt's output files:
- `target/run_results.json` — which models passed/failed, test results
- `target/manifest.json` — node dependencies, source definitions (used for DAG rendering)

### `objective_checker.py`
Evaluates each objective's check condition. Returns `CheckResult(passed, reason)` with specific diagnostic messages on failure. Check types:
- **File content**: `has_column_alias`, `has_ref_call`, `file_contains`, `file_contains_active_sql`, `no_hardcoded_refs`, `has_test`, `has_freshness_config`
- **Artifact**: `all_models_pass`, `model_passes`, `tests_ran_with_failures`
- **DuckDB**: `duckdb_column_exists`

Near-miss detection catches typos (e.g., `timestanp` suggests `timestamp`).

### `narrative_engine.py`
Matches game events against narrative triggers defined in the level YAML. Returns a list of narrative messages to display, sorted by priority (high → normal → low). Tracks which triggers have fired to prevent duplicates.

### `state_manager.py`
Reads/writes `.stellar_state.json`. Tracks: current level, XP, badges, completed objectives per level, fired narrative triggers, run/test counts, pending narratives.

### `_sql_helpers.py`
Regex-based SQL alias extraction. Used by the `has_column_alias` objective check. No sqlglot dependency — just pattern matching for `column AS alias` in SQL.

## `stellar_dbt/levels/` — Level definitions

### `__init__.py`
Empty. Package marker.

### `loader.py`
Loads level YAML files and applies them to the dbt project. `apply_level()` wipes the models/ and macros/ directories, writes base files (stg_planets, sources), then writes level-specific files from `initial_files`. Also handles seed file swaps and database cleanup for clean level transitions.

### `level_01.yml` through `level_05.yml`
Each level defines:
- **Metadata**: title, subtitle, character, XP reward, badge
- **locked_files**: files the player can't edit (read-only references)
- **seed_files**: CSV overrides for source data (e.g., Level 2 adds NULL shipment_ids)
- **initial_files**: file templates written to disk when the level starts
- **objectives**: ordered list with labels, hints, and check conditions
- **narrative_triggers**: which game events fire which narrative messages
- **narrative_script**: the actual dialogue text, keyed by name

Level progression:
1. Staging, ref(), source(), joins, aggregation
2. Tests (not_null, unique), source freshness
3. Documentation, accepted_values tests
4. Incremental models, unique_key, is_incremental()
5. Macros, CASE WHEN, investigation model + story resolution

## `frontend/components/`

### `StartMenu.tsx`
Animated title screen. Typewriter-style text crawl setting up the sci-fi story, starfield background, "BEGIN MISSION" button. Click to skip animation.

### `GameShell.tsx`
Main layout. Three-column grid: left sidebar (files + objectives), center (editor + bottom pane), right (narrative + terminal). Manages all game state, handles level loading/switching, keyboard shortcuts (Cmd+Enter for dbt run, Escape to close preview).

### `StatusBar.tsx`
Top bar. Logo, level selector buttons (1-5), level title, XP progress bar, earned badges, reset button, "dbt run" button.

### `FileTree.tsx`
Left sidebar file browser. Groups files by folder, shows lock icons for read-only files. Also lists source data tables (raw_shipments, raw_planets) with row counts — clicking one opens DataPreview.

### `ObjectivePanel.tsx`
Left sidebar objective checklist. Shows checkbox indicators (current = cyan arrow, done = green check), labels, and failure reasons in amber. Highlights newly completed objectives.

### `CodeEditor.tsx`
Monaco editor wrapper. Custom "stellar-dark" theme matching the UI colors. Saves on blur and Cmd+S. Shows "READ ONLY" badge for locked files. Keyed on file path for clean switching.

### `DataPreview.tsx`
Source data table viewer. Shows raw CSV data with column headers, NULL highlighting in red, voss_flag=1 highlighting in amber. Closeable with X button or Escape.

### `TerminalPanel.tsx`
Right sidebar terminal. Shows dbt stdout/stderr output with ANSI codes stripped. Action buttons: "dbt run", "dbt test", "check". Auto-scrolls to bottom on new output.

### `NarrativePanel.tsx`
Right sidebar COMMS panel. Shows character dialogue with color-coded names and `<highlight>` tag rendering. New messages fade in with lightning bolt icon. Old messages dim to 50% opacity and remain scrollable. Auto-scrolls to latest.

### `BottomPane.tsx`
Tabbed bottom pane below the editor. Two tabs: DAG (lineage graph) and PREVIEW (query model results). Model selector buttons appear on the preview tab. Refreshes after each dbt run.

### `DagView.tsx`
Pure SVG DAG renderer. Topologically sorts nodes into layers, draws edges with status-colored lines. Sources/seeds get dashed borders, models get solid. Node colors reflect run status (green = success, red = error, gray = pending). No external graph library dependency.

### `ResultsPreview.tsx`
Queries a built model from DuckDB via `/api/preview/{name}` and renders a data table. Shows "Run dbt run first" if no database exists yet. Used in the BottomPane preview tab.

### `LevelComplete.tsx`
Modal overlay when all objectives pass. Shows badge emoji, badge name, XP earned, and a "Continue" button.
